# 团队密钥网关

目标是让团队成员使用共同额度，同时看不到上游原始 key。这里采用开源 LiteLLM Proxy；真实 key 只放在网关服务器的 `.env`，每位成员使用独立虚拟令牌。

## 部署

需要 Docker。复制 `.env.example` 为 `.env`，生成三个高强度随机值：管理密钥、稳定盐值、数据库密码；再填写服务商 key。

```sh
docker compose up -d
```

默认只监听 `127.0.0.1:4000`。团队跨电脑使用时，请通过 Tailscale、公司内网或带 HTTPS 的反向代理连接，不能直接暴露明文端口。生产环境还应限制管理页面的访问来源。

用管理密钥登录 `http://127.0.0.1:4000/ui`，为每位成员创建独立虚拟令牌，分别设置可用模型、预算和有效期。成员离队或设备丢失时，只撤销该成员令牌，不需要更换所有上游 key。

## 成员接入合流

在“模型配置”中选择“团队网关令牌”：

- 接口地址：网关的 HTTPS 地址，以 `/v1` 结尾
- 模型 ID：`deepseek-team` 或 `kimi-team`
- 团队令牌：管理员为该成员单独生成的虚拟令牌

成员令牌仍属于敏感信息，只能发给对应成员，不能放进仓库、群公告或截图。合流只在成员本机加密保存令牌，页面不会回显。

## 安全边界

- 不把上游 key 加密后发给成员；客户端最终能解密，就等于已经交付原始 key。
- 不把 `.env`、数据库目录、管理密钥或虚拟令牌提交到 Git。
- 每人一枚令牌，分别限额、审计、撤销；不要让多人共用同一令牌。
- 日志默认不要记录提示词正文。先确认公司数据政策，再开启内容日志。
- 此模板不预置百炼个人 Token Plan。个人套餐通常带设备、账号或使用方式限制，不应当作团队共享额度；请使用允许团队调用的企业套餐并遵守服务商条款。
- 更新 LiteLLM 镜像前先阅读发布说明并在测试环境验证；当前模板固定为 `v1.101.0`。

LiteLLM 官方文档：https://docs.litellm.ai/
